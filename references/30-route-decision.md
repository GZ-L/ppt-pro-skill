# 30 Route Decision

Use this reference before choosing the production path. Choose the final deliverable shape, not another Skill chain.

## Required Questions

Ask or infer, then confirm:

- Does the user need a `.pptx` file?
- Must text, shapes, charts, and tables remain editable?
- Will the deck be submitted, presented live, shared with a team, recorded as video, or posted as content?
- Is motion or responsive web presentation important?
- Are there existing brand assets, templates, screenshots, or source files?
- Is the user asking to beautify an existing deck or create a new one?

## Route A: Editable PPTX

Choose this route when the user needs:

- School assignment, company report, client proposal, pitch deck, lesson slides, team collaboration, or formal submission.
- A `.pptx` file that works in PowerPoint, Keynote import, WPS, or Feishu import.
- Editable objects and future manual revision.

Required package:

1. `user-confirmation.md`
2. `deck-brief.md`
3. `outline.md`
4. `style-match.md` when style references are used
5. `style-board.md`
6. `production-route.md`

Avoid this route when the user mainly wants cinematic motion, responsive web scenes, or a video-first deliverable and confirms that PPTX is not required.

## Route B: Visual Web Deck

Choose this route when the user confirms:

- High-aesthetic visual storytelling.
- Keynote-style motion, launch film feeling, product demo, web slides, screen recording, or short-video reuse.
- Strong control over layout, animation, responsive framing, and screenshots.

Avoid this route when the required final deliverable is an editable `.pptx` unless a dual route is confirmed.

## Route C: Dual Version

Choose this route only when the user confirms they need both:

- formal editable PPTX
- visual/motion version

Recommended sequence:

1. Make the shared story package: confirmation, brief, outline, style match, style board.
2. Produce both versions from the same page jobs, titles, terminology, and source notes.
3. QA separately: visual version for motion/framing, PPTX version for editability.

Use this route only when the extra effort is justified.

## Route D: Review Only

Choose this route when the user asks to review, critique, diagnose, or "先看看" without producing files.

## Existing Deck Beautification

When the user provides an existing deck:

- Preserve required content, meaning, slide order constraints, and citations.
- Diagnose each slide by message, density, hierarchy, layout, color, typography, image/chart quality, and editability.
- Decide whether to revise slide-by-slide or rebuild from outline.
- Keep a changelog of major content or layout changes.

If the existing deck is image-only or flattened PDF, state the editability limitation before proceeding.
